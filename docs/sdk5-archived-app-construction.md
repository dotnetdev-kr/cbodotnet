# Archived SDK5 App construction

The additive `musl_legacy5_appinsights_archive` and `musl_legacy5_appinsights_archive_normal` modules validate archived App supplier bytes without starting a compiler, Reader, container, Git command or .NET runtime. They do not activate a release route or change the original worker, strengthened private validator, live normal adapter, consumption selector or default schema.

`reconstruct_app` takes an independently authenticated sealed parent record, its original normal context/prepare/stages, the actual delivery directory, five actual external archive paths, an actual indexed consumption-capture root, a fresh verification directory and explicit storage budgets. The SDK descriptor must already be present in the authenticated canonical parent record. The normal leaf never substitutes the producer's SDK descriptor for the caller's descriptor. A saved successful receipt, descriptor dictionary or private retained control cannot supply the reconstruction capability.

The complete source archive and index are captured as immutable byte streams and verified together: member order and closure, byte hashes, Git objects, baseline trees, original file modes and registered roots. The source manifest and its CI copy must agree with the sealed inventory. SDK5 uses a separate source session; the existing SDK7 source session is unchanged. Source traversal preserves the original two-million-member capacity and discards `tarfile` member caching during streaming. Complete source archive/index/expanded-byte storage is charged separately from the private App budget.

The public App root must have exactly 493 indexed and inventoried members: the original public449, seven normal records, 29 output files and eight package/provenance records. Both Csc intermediates and all three actual Reader generated C# sources are mandatory. The source index authenticates original executable modes even when artifact download transport has lost those modes. A mode can be coupled only from a same-session actual indexed body and before delivery provenance is minted.

The external inputs are exactly `referenceZip`, `comparisonPackage` and `compilerArchives`, whose keys are `legacy5`, `runtime` and `vstest`. They name five distinct ordinary files. Complete actual ZIP/NPK hashes and the original worker's reference-member and assembly-identity predicates reproduce private73. These bytes are materialized only into the private full522 workspace. Their origin remains the finite external reference/comparison role; it is never presented as a payload or source-built binary. The complete input manifest and all original worker input/Git/mode checks must agree with the full522 tree.

All three original compiler archives are authenticated against the original role/CPU pins and fully inventoried from their immutable captured streams. Every original entry receives the original type/path/mode/duplicate/size guards, including entries outside the selected matching-runtime prefix. The two complete BOOT trees are reconstructed once. The SDK5 matching runtime is merged only into an exact, disjoint SDK inventory; the two source-native substitutions require their actual captured libraries and unchanged support predicates. Composition and inspector receipts must reproduce exactly. The unchanged independent native-source validator remains mandatory. Its existing positive is restricted to aarch64; this additive module does not invent an x64 positive.

`FrozenView` keeps host, container and consumer path namespaces distinct. Original JSON and argv paths remain unchanged. The one historical Copy destination containing `dotnet//sdk` is preserved as an exact consumer key; other aliases and parent components reject. A source or delivery mapping requires a concrete factory-minted origin, not arbitrary snapshot bytes. A delivery origin binds the canonical authenticated parent record. A source origin binds the exact complete source archive/index/root/member/mode/fingerprint. Missing mappings never prove absence: normal private-record absence and selected root closure query the complete immutable index.

Full physical validation is POSIX-only. Before delegating reads, the owned view hashes every physical file through retained read-only descriptors, captures inode/mode/size/mtime/ctime witnesses for files and directories, and rejects unmapped extras. Descriptor capacity is checked before those opens. Every delegated guard checks the mapping and physical witnesses before and after reads, so changing a file and restoring its bytes and mtime still fails through ctime. Incoming paths are not reopened as proof. Complete public delivery artifacts needed by unchanged path-based predicates are copied into the owned private delivery view and charged to the public-session budget; no second expanded source tree is created.

The original compiler-record functions, process/log/Reader bindings, exact API comparison and package body predicates run on the reconstructed four host roots. Both actual raw binlogs are decoded by the reviewed original-import parser and compared with the independently reconstructed host bytes, Csc context/argv, Mono edges and explicit false-condition evidence. The five retained output-origin records must match the actual Csc facts. The complete package bytes must equal the unchanged deterministic five-member ZIP writer, including metadata and all container bytes; hidden comments, extra fields and trailing padding reject.

Returned compiler final-output paths are explicitly recorded as verification paths. When comparing an original receipt, a separate fixed-path observation retains the predefined original attempt path and independently verified fingerprint. Original contexts, commands and receipt bodies are not edited to imitate a live workspace. The archived normal boundary revalidates all original field predicates, actual parent preparation/build, complete input before/after inventories, source identities, engine reports, diagnostic mount boundaries and observed default security before existing shared validators read them.

Only after these actual predicates succeed does the factory mint `ReconstructedApp`. Its source/view/delivery references and complete application/context/record/root facts are bound at mint and rechecked before consumption. The consumer module accepts this concrete capability and recomputes the original SDK proof, toolset, all cache/feed/Copy observations, source artifact, final archive and optional Crossgen predicates. Actual captured cache/Copy bytes come exclusively from the closed authenticated capture root, never from copying the newly reconstructed supplier DLL. Saved normal-consumption flags do not supply a verdict.

`validate_archived_app` establishes the narrower App component construction gate after genuine reconstruction and actual captured SDK consumption. It explicitly leaves `fullPublicConstructionValidated`, whole-producer source closure, qualification and source admission false. Complete private-content exclusion across **all** delivery/source/package bodies and the parent SDK construction/source closure remain separate aggregate gates. The existing `R.validate_public_construction` is not delegated or relaxed by this implementation. Root-owned integration requires a separate review and genuine bounded positive; the old private two-log success is not a normal archived positive.

Budgets explicitly separate private reconstruction, complete source-session bytes and owned public artifact/session bytes. The private touched budget cannot exceed 2 GiB. All materialization reserves bytes and file counts before allocation or writing; large snapshots and expansions additionally require measured free space plus a 512 MiB reserve. Original BOOT inputs count as touched in addition to their immutable captured copies and the single reconstructed BOOT pair. The parent must measure complete source/index/public artifacts, actual file-descriptor capacity and CPU-specific inputs before authorizing any real control. Historical ARM64 sizes cannot be reused as x64 measurements.

Ordinary tests use tiny generated archives, source Git-object fixtures and actual immutable origin factories. They cover byte/index mismatch, modes, malformed TAR/PAX and record-boundary padding, linked paths, namespace/descriptor spoofing, nested metadata mutation, source closure, private-record absence, before-write budgets, BOOT merge/adoption, file mutation with restored mtime, container-hidden package bytes and normal/parent/security failures. They do not create a fake `ReconstructedApp`, run a retained original log/archive control or establish a full consumer positive.
