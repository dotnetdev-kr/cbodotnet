.NET 6 uses a generated installer source-build tree. The earlier versions use their pinned direct source-build orchestration. .NET 5's final serviced source-build branch produces SDK 5.0.214, while the latest published SDK across bands is 5.0.408. The final Core 3.1 source branch supports SDK 3.1.426, so it need not be restricted to a 1xx band. Core 3.0 uses a corrected source tag whose annotation explicitly replaces an earlier tag with the wrong ASP.NET revision.

Each version has separate source, input and container-home directories on D-backed Linux storage. Existing SDK archives, reports and environments remain preserved. Build scripts are frozen per attempt, and failed or interrupted actions retain separate evidence. Native compilation and SDK tests run on ARM64 without CPU emulation.

The retained old official SDK images provide the OpenSSL/ICU generation required by historical bootstrap tools. A low-ABI sysroot and the final dynamic-library requirements still require per-native-component verification. Older runtimes may require explicitly recorded compatibility libraries in newer verification user spaces; no invariant-globalization workaround or untested stock-OS compatibility claim is used.

The original Darc packages for .NET 5 and Core 3.1 are no longer available at their declared endpoints. The new guarded source-acquisition adapter replaces only that clone operation. It validates pinned root manifests, fetches full component histories, exports exact commits and recursive gitlink-pinned submodules, and records immutable initial inventories. Upstream metadata generation, source patches, component builds and completion logic remain active. Local Git fixtures and peer review passed before real acquisition began.

All four legacy targets have completed SDK packaging, local framework/native origins, their complete applicable upstream suites, three-user-space functional/ABI verification, unchanged archive collection and strict delivery audits. The local build goal is complete. Core 3.0's supported incremental completion remains separate from the earlier failed full graph. All four final manifests bind the same 185 current project build-input records. No CI migration or binary publication is part of this run.

The added legacy branch of the native verifier has separately passed all six functional checks against retained official SDK inputs for .NET 5, Core 3.1 and Core 3.0. These validate the verifier, not a community product build. Core 3.0's Python 3.6 processes require a real UTF-8 filesystem locale to compare the non-ASCII certificate filenames in the signed sysroot faithfully; `LANG=C.UTF-8` and `LC_ALL=C.UTF-8` are explicit harness inputs. The direct-source collector passed 90 identity/boundary fixtures, and the unchanged .NET 6, 7 and 8 collector regression fixtures passed.
