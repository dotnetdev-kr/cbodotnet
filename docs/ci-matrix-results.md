## Source contents and verification boundary

Each delivery contains the unchanged SDK archive, SDK checksums, complete reports, a validation envelope, and a `sources` directory with the actual source archive, JSON Lines file index and source manifest. The source manifest also appears in the inventoried CI reports. The index binds actual file bytes, symlink targets, modes, deletions and Git baseline identities; verification reconstructs the pinned baseline trees and checks the complete source archive.

Product source roots include the actual patched consumers and recursively pinned submodules. Generated source roots retain the adapter-declared inputs and exclusions. The .NET 6/7 generated adapter snapshot also includes some generated test output files; these are indexed explicitly and do not substitute for product source. The .NET 10 4xx profile additionally supplies the complete matching 1xx VMR sources for reused shared frameworks, tied to both delivered `.version` markers. Those frameworks remain disclosed upstream binary inputs.

These archives preserve product and orchestration sources. They do not contain Git object stores, an offline bootstrap environment or all source corresponding to every binary tool/reference input. Construction scope, retained inputs and explicit legacy compatibility dependencies remain recorded in the manifests and version-specific reports.

Portable verification checks both transport hashes, safe extraction, SDK/report/source content, expected commit/run/attempt and each version's original qualification gates. It executes verifier code from the trusted checkout; downloaded orchestration and source files are evidence only. CI artifacts use the workflow's 14-day retention. Optional unpublished drafts remain a separate manual choice.
