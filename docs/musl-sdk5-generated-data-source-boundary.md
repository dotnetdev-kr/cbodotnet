# SDK5 four data outputs and copied task providers

`musl_legacy5_generated_data.py` checks a closed, partial byte boundary for
SDK5.0.214/aarch64. It covers the original runtime graph, runtime chain and the
two dotnet-dev-certs/dotnet-user-secrets runtime configuration files. Their
three original complete NPKs and13 authored recipe source files retain exact
fingerprints and Git blob identities. Source input values are actual bytes or
ordinary file paths; package/output inputs must be ordinary file paths.

`reconstruct(source_files, packages, rid='linux-musl-arm64')` accepts the exact
policy key sets. It reproduces the51,396-byte original Git graph's3198 LF to
CRLF conversions, matching the54,594-byte original package/final graph. This
declares observed byte correspondence; it does not infer a historical checkout
mechanism. Original graph expansion reproduces the70-byte runtime chain.
Both original147-byte CRLF configuration package members retain their bytes
except for the actual5.0.0 to5.0.17 replacement, producing148-byte outputs.
These JSON members are publisher generated data. They are separate from the
AspNetCore authored project recipes and are not called literal Git JSON source
or an observed publisher SDK execution. `validate_reconstruction` compares all
four supplied actual output files. An x64 algorithm result is not an x64
production observation and this first leaf rejects it as a construction RID.

`provider_identities(actual_output_root, packages)` checks all13 copied PE
members, their complete11 original NPKs, exact task/ref/deps files, original
PE dependency metadata and declared runtime/Windows asset distinctions. It
deduplicates source requirements by repository plus exact commit. Common,
Configuration, Frameworks and Versioning5.8 share830c8be; Packaging5.8 uses
ebc4f817. The separate rebuilt5.9 component cannot substitute for these inputs.
Pkcs and ProtectedData retain distinct original runtime/corefx commits and
both Windows variants. Json9 retains its existing original publisher ZIP/source
policy and no invented nuspec or embedded Git commit.

The three original MSBuild15.7.179 PEs contain the shortened informational
identity `15.7.179+gac19036b0d`. Its official primary commit resolution is
ac19036b0de4f1b58c3be76d51000df8db98560c. The policy records this separate
short-prefix basis; it never calls it an original full embedded SHA.

Copied assets, Csc references and a deps file do not show which assembly the
CLR loaded. Hosting may supply a framework or MSBuild contract from the
authenticated bootstrap. Source archive/object/mode validation for every
origin, actual installer Csc and task/provider load binding, actual task
parameters/chronology and Copy/final archive binding remain required. Every
result carries partial scope and admission=false. `validate_full` fails closed;
descriptors, positive markers or callbacks cannot provide a successful branch.

No entry fetches sources, executes .NET/Reader/MSBuild/containers or rewrites
the original235 unknown observations,618-path correspondence, raw artifact
