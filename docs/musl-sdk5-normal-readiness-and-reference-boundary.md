# SDK5 normal producer readiness and finite reference-bootstrap proposal

Status: reviewable design, not admission policy or an execution authorization.
The SDK5 normal route stays closed. No existing worker, archive, source role or
validator is changed by this document. The actual private v8 attempt remains
failed; the separate unchanged68-case smoke rerun is a diagnostic success.

## What the existing predicates actually require

The original SDK5 bootstrap policy enumerates three exact archive roles:
`legacy5`, its matching `runtime`, and the separate `vstest`/Reader SDK6.
`musl_legacy5_bootstrap_byte_inputs.validate` hashes their complete original
members, reconstructs the two actual compiler trees and authenticates the two
source-built native support adaptations. Its records explicitly distinguish
`bootstrapCompilerRoleOnly`, `payloadRole=false`, original publisher binaries
and source-built support. It does not require preferred C#/IL source for every
original compiler/runtime bootstrap byte. Native crypto/trace source closure is
a separate mandatory leaf. This finite tool bootstrap contract already exists;
it is not a general permission to omit arbitrary binary inputs from evidence.

Profile7 is not in those three named bootstrap archive roles. The immutable
App worker's `prepare` and `verify_inputs` require the complete522-member typed
tree, including `reference.zip`, all70 selected Profile7 files, the separate
base FrameworkList XML, original authored sources/targets/license, original
comparison NPK and Reader/execution inputs. The original source roundtrip
captures that full tree. The stronger private validator and the new normal
adapter both still require those actual private input bytes. Their success
does not establish source or license coverage for the reference binaries.

There is currently no complete A5 normal entry that states an independent
global rule requiring historical preferred source for every nonshipping
compiler reference. There is also no existing App descriptor-only export or
validation entry. Omitting ZIP/PE bytes while claiming the old full522-tree
source proof would violate its exact predicates. The current normal adapter
places the actual attempt under delivery reports; publishing that whole tree
would redistribute the ZIP. That layout must not be silently called private.

Existing BOOT byte validation also reopens the actual three archives; a public
descriptor is not a substitute for those byte checks. A corresponding finite
reference boundary must likewise require separately acquired actual bytes at
its full validation boundary. Public product source, privately acquired tool
inputs and the evidence needed for complete validation are distinct objects.

## Proposed single finite reference-bootstrap role

This section proposes an additive, separately reviewed role named
`sdk5-app-profile7-reference-bootstrap`, with `payloadRole=false`. It is limited
to the exact ZIP already pinned by immutable policy91980fa1, its70 selected
Profile7 members/65 DLL identities and the separately pinned base FrameworkList
XML. It permits no version/TFM/profile substitution, additional assembly,
retargeting, alternate image, App source modification or raw artifact-kind
change. The original worker/strong validator and full522 private inputs remain
unchanged; old public/full source packets remain preserved.

The origin descriptor must retain the complete ZIP size/SHA256/SHA512, original
URL, publisher/release identity, full member names/sizes/modes and selected
member three fingerprints. The closed65 assembly identities come from the
unchanged decoder and original policy. The full955-entry original ZIP has an
independent name/mode/size/Git-blob correspondence to official Mono packaging
upstream874cf94, tree8f28f2cb. Packaging merge46afb directly parents that tree
and contains the Microsoft PCL4.6 EULA candidate. Keep these binary origin and
license-candidate facts separate from authored preferred source. They do not
make the repository a historical C#/IL source tree or establish legal coverage.
The ZIP's absent embedded license and the non-free/EULA status remain explicit.

The private input boundary must reopen the exact original ZIP, compare all70
selected members and base XML with the immutable policy, decode all65 DLL
identities, and check the actual extracted private reference files and modes.
The actual App Csc task and complete command must contain exactly those65
reference paths. Each observed reference fingerprint must equal the exact
private member and policy fingerprint. Retain the unchanged full522 manifest,
normal container/engine/security records, actual compiler/Reader provenance,
both original binlogs, separate replay status/tasks and all output fingerprints.
No descriptor alone can prove compiler execution or byte consumption.

The normal product-source export could be a new explicit object containing:

- all437 original App Git files and original source license/public key;
- the exact four authored Mono targets and separate original omnibus LICENSE,
  their real Git identities, and the proven complete provider/import closure;
- original adjunct/execution/strong/normal adapter source, generated metadata,
  actual compiler/Reader/API/package/consumer evidence and origin/use manifests;
- the closed reference-bootstrap origin/member/identity descriptors and the
  explicit requirement to acquire the pinned binary input separately.

The full private typed tree must stay separately retained. A new public export
must have its own name, role, exact allowlist and full byte/mode mapping to
that private tree. It must not replace or relabel the original full typed root
or pretend its public subset passed the old full-tree validator. The default
private worker and its successful proof must continue to validate unchanged.
The adapter's delivery layout and final report inventory need explicit review
before any public export omits private reference inputs. No redaction or move
is implemented by this proposal.

An independent public verifier may validate complete authored product source
and descriptors without redistributing the ZIP. Full construction validation
must additionally receive/reacquire the exact original reference bootstrap
and original compiler bootstrap archives, perform their actual byte checks,
and reconstruct all65 Csc reference identities/use. If only descriptors are
available, the result must say that full construction validation is pending.
This is a proposed finite trust boundary consistent with named compiler-tool
bootstraps, not a blanket binary-source exception or a completed old proof.

## Nonshipping and license gates

The new App NPK must have exactly its five reviewed members: local DLL/PDB/XML,
original source LICENSE and source-derived nuspec. It must contain none of the
reference files or reference ZIP. The complete actual toolset and final SDK
inventories, including every shipping embedded NPK/member, must independently
exclude the reference ZIP and every one of the65 reference DLL fingerprints.
The private input directory must not enter the public product/source/report
export. A path-name exclusion alone is insufficient; compare actual contents.
Any observed overlap fails and requires product-specific analysis; it cannot
be explained away by the proposed bootstrap role.

Keep compile-use authorization, binary redistribution permission and preferred
product source separate. The candidate EULA may explain input acquisition/use;
it is not a conclusion that redistribution is permitted. Not redistributing
the binary ZIP would remove that proposed export operation, not establish
compile-use permission by itself. The Mono source LICENSE is an omnibus notice
and does not automatically cover the ZIP. Root/peer review must settle the
finite role and the actual applicable terms before whole admission.

The four Mono target files also import other providers. The existing65-reference
check does not prove that import graph. Retain/reconstruct the actual original
App evaluation/import closure from its original binlog and exact sources,
including selected bootstrap Common/CSharp and conditional VS CurrentVersion
imports. Bind each used authored target to actual source or the separately
enumerated exact compiler-bootstrap input. Unobserved optional branches cannot
be accepted as actual execution. This import-use gate remains open.
