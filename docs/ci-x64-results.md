## Delivery and measurement boundary

Every qualified delivery includes the unchanged SDK archive and checksums, complete reports, validation envelope, actual used source archive, JSON Lines file index and source manifest. Source capture records patched files, symlink targets, modes, deletions, original Git baseline identities and declared generated-source exclusions. Pinned submodules and the complete matching .NET 10 shared-input source tree retain their separate source roles. Generated .NET 6/7 snapshots also include explicitly indexed test outputs.

These archives preserve product and orchestration sources, not a complete offline bootstrap environment or source for every binary tool/reference input. The regular .NET 9/10 framework reuse and all original/prebuilt inputs remain explicit. No zero-prebuilt, Stage 2 or reproducibility claim follows from this qualification.

Portable verification checked both transport hashes, safe extraction, SDK/report/source bytes, expected commit/run/attempt and every matching family gate. It executed trusted checkout code; downloaded source and orchestration files were evidence only. Actions artifacts use 14-day retention. Native checks cover the recorded Ubuntu 22.04, Ubuntu 24.04 and Debian 13 user spaces, not every kernel, distro, optional diagnostic component, workload or external native package. Legacy OpenSSL/ICU inputs remain separate from the unchanged SDKs.

All eight runs used the standard native `ubuntu-24.04` GitHub-hosted worker without paid-runner fallback. The original preparation thresholds stayed 30 GiB for .NET 10 and 90 GiB for the other profiles. Resource samples cover grouped product/test/source/native work after preparation and are not isolated process-tree peaks or guaranteed minimum capacity. Qualification establishes feasibility for these exact inputs, not a capacity guarantee for future SDK revisions.
