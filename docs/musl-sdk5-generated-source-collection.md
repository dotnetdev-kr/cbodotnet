# SDK5 generated-data/provider corresponding-source registration

`musl_legacy5_generated_collection.py` is an explicit partial source collector.
It derives nine exact origins from the four-data/provider and Json publisher
policies. Existing primary40, extra4 and literal17 policies remain unchanged.
The caller first installs those source hooks, then calls
`register(sdk, sources, clone, expand_submodules, report_path, workspace=W)`.

The four prior roots are installer430330f7, AspNetCore02c6de4,
ProtectedData/corefx8321c729 and Json9 publisher e5ac9a84. Five possible fresh
parents are graph/runtimef431858f, NuGet830c8be and ebc4f817,
Pkcs/runtimeb0377846, and MSBuildac19036b. Existing authenticated Gitlinks can
satisfy them. Logical origin comparison permits only HTTPS GitHub owner/repo
case and final.git normalization. Local origins, another repository and an
unproved redirect alias cannot substitute. Exact HEAD/commit object/tree,
actual child path/commit and original.gitmodules URL binding are required.

MSBuild's source checkout has the full ac19036b... Git commit. Original PEs
retain their separate short `15.7.179+gac19036b0d` provenance. Json9 retains its
original publisher ZIP/source policy. Package metadata is never synthesized.

Existing source records, paths and compiler roles stay intact. A fresh clone
must use the absent fixed `W/work/<name>` destination. Only fresh corresponding
roots and their actual fresh Gitlinks reach the original raw-Git materializer,
followed by exact Git blob/type/mode checks. Reports remain outside every old,
new and expanded source root before any materialization or report write.
POSIX source-mode behavior is verified on Linux; Windows cannot establish a
positive POSIX materialization proof.

Actual existing origin/HEAD/tree identities are snapshotted before the first
expansion and again after original children are discovered. They are compared
after clone/expansion callbacks, before any fresh materialization, and before
the report. Changing an unrelated old remote or dropping a protected physical
root therefore rejects even if the caller's source-record dictionary stayed
unchanged. Failed captures are not turned into successful receipts.

The frozen future disk/file limits are proposed acquisition limits owned by the
caller. This registration callback does not enforce or prove source-fetch
bounds. The receipt reports measured fresh Git content separately and keeps
source-archive validation, actual provider loading, qualification and admission
false. Root must still provide the measured acquisition helper, complete source
archive/object/mode validation, actual original task/provider execution and
independent A5. Importing this module acquires or materializes nothing.
