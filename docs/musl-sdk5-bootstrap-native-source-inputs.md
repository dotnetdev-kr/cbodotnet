# SDK5 compiler-bootstrap native source inputs

This separate leaf complements the reviewed bootstrap byte-construction guard.
It reads the full authenticated runtime baseline and actual bootstrap support
data roots from the used-source archive. Crypto source copies must contain all
72 original Common/crypto/configure files, with original executable modes. Only
the exact two declared OpenSSL patch sections may differ. The external driver
and its complete Common copy follow the immutable original worker recipe.

Trace inputs include the original three Python modules, event manifest, and
the runtime include trees selected by the recorded compiler argv. The twelve
generated CPP/header files have immutable bytes and modes independently
reconstructed by the original authenticated upstream Python generator. The
validator does not execute that generator. Later declared native-CoreCLR
patches are reversed only for their exact original source sections; C/C++ line
endings and executable modes have no normalization exception.

The caller must first run the complete source-packet verifier. The existing
full native runtime source validator is also reexecuted against that packet.
Actual bootstrap support reports must equal their complete archived data trees.
No compile-time hashing or missing compiler-database observations are invented.
The complete A5/normal worker/consumer admission gates remain separate and closed.

Generated include directories have a closed91-file name/mode inventory as well
as exact graph/flags/config-header byte pins. An extra nested `openssl/ssl.h`,
response file, or other shadow input is rejected even if actual and archived
trees are changed consistently. The full entry explicitly rejects x64 until a
separate observed source/graph positive is reviewed.
