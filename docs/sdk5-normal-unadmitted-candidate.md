# Private normal SDK5 candidates

`musl_legacy5_candidate` and `musl_legacy5_candidate_collect` are additive APIs
for retaining already-completed genuine normal SDK5 facts. They provide no CLI,
build execution or publication wiring. The SDK5 dispatcher, existing producer
collect/seal stubs, common receiver/admission and `R.validate_public_construction`
remain closed. No workflow automatically uploads these candidate deliveries.

The collector requires actual passed prepare/build/scan/test/verify records,
the original normal App context, actual source roots and the raw E5 emitter's
normal evidence context. It does not obtain missing builds or repair diagnostic
records. It runs the original raw emitter, retaining every unknown and original
repository attribute. The original build report, E5 proof and actual final SDK
must already have identical name/size/SHA256/SHA512. That descriptor is present
before original M consumption validation and C capture. Packing occurs after the
checked App and capture roots have been registered. A real failed action or
authentication writes an honest failed collect journal, never a success seal.

Full authentication is POSIX only. The factory repeats original live M
validation, verifies C's complete actual data against those recomputed facts and
live cache/feed/Copy bytes, and verifies the complete final source packet with
the existing SourceSession. The App493 and capture roots must match the actual
complete D inventory through the original same-session origin factory. The
archived orchestration must contain exact normal-worker and candidate code.
Source packing proves byte/index/Git consistency; semantic source closure and
raw unknown resolution remain separate.

Only after source/SDK/stage/capture/code/D checks pass does the factory atomically
promote a private, caller-owned metadata directory outside D/W/J/BOOT. Its
staging and seal also exclude every original source path in both the explicit
source-roots journal and the final source manifest before snapshot writes.
Raw E5 proof rereads preserve exact bytes through the same bounded stable reader.
Its
`candidate.json` has a distinct kind and `status: retained-unadmitted`; its
`record.sdk` is the unchanged original descriptor. `record.files` binds every
actual D file. The factory never writes `producer-validation.json` and refuses
a D containing it. Candidate access checks the sealed bytes and complete current
D again. A caller cannot mint `AuthenticatedNormalCandidate` from a saved
successful receipt or descriptor dictionary.

The capability's canonical `record` and `normal_context` can supply the existing
archived App API after a separate genuine bounded control is authorized. This
factory does not mint ReconstructedApp, claim an archived full App positive or
invoke the R aggregate. Full-public construction, semantic source closure,
all-D private-content exclusion, qualification, download availability and
installer admission remain false. In particular D stays private: App/capture
subtree scans do not prove that all SDK/source/package/container bodies are safe
to publish.

The existing native bootstrap source guard is aarch64 only. A candidate record
does not provide an x64 BN positive, permit x64 to inherit ARM64 inputs or change
any native rebuild policy. Complete source/worker/license and per-CPU resource
gates, independent aggregate A5, fresh normal two-CPU provenance and protected
source/consumer publication remain separate requirements.

Ordinary tests use tiny actual files, TAR/NPK/source-index bytes and original
byte predicates. Mocked collection tests stop at authentication and establish
only ordering/failure behavior. They never count as genuine parent, App,
capture or qualification positives. Windows focused tests do not establish
POSIX factory or atomic-retention success. No actual retained input/control,
compiler, Reader, runtime, container, Git or network is exercised by them.
