# Core3.1 normal construction contract: first, unregistered slice

The dedicated policy and read-only validators establish accounting boundaries for
the genuine SDK3.1.426 construction graph. They do not register a producer, grant
source/release admission, run a worker or change an existing SDK contract.
`ROUTES`, common `SOURCES`, profiles, release/catalog code and all29 workflows
are outside this change. No current release consumes these files.

The retained private SDK71 → CLI72v3/localized F#76 → toolset79v3 → core-sdk80 →
collector81 chain establishes which original projects and package roles matter.
Its products and receipts remain historical reference evidence. In particular,
collector81's1,955-file ARM64 archive is neither the required hash/count for a
new build nor a normal product. It fails the new normal-admission boundary.

## Policy and byte-accounting APIs

`musl-legacy31-construction-policy.json` records the12 known original source
roots, the seven-stage parent graph, per-CPU bootstrap facts, selected own-built
roles, individually named import candidates and explicit missing evidence.
Those12 roots do not claim complete transitive source closure. MSBuild, Roslyn,
NuGet, VSTest, PlatformAbstractions and every actually selected shared/generated
or submodule input still require their original source/member/license contracts.
Missing SHA512 values remain null; ARM64 facts do not fill x64 gaps.

`musl_legacy31_construction.py` is import-safe. Its functions authenticate complete
size/SHA256/SHA512 values, inventory bounded TAR/ZIP bytes without extraction,
recheck ordinary directory layouts against canonical manifests, verify actual
Git blob/tree/commit objects and account exact private SDK PE/data selection.
Every archive call needs explicit compressed-byte, member, per-member and
expanded-byte ceilings. Gzip inflation includes TAR padding. Special members,
escaping links, duplicate/aliased names and PAX path redirection are rejected.
Raw policy/NuGet rereads bound allocation before reading and reject changed file
state; layout entry limits apply while consuming scandir, before sorting. No
archive member, compiler, package script or assembly is executed.

The existing pure `musl_nuget_content_hash` helper is the sole repository-code
dependency outside these dedicated modules. Actual NuGet contentHash is checked
separately from whole signed-file SHA512. This does not verify a package's
signature or grant source qualification.

Reachable Git-history size and the original `GitCommitCount` property are
different metrics. `verify_version_count` requires an independently approved
target identity, declared original algorithm/base and complete authenticated Git
history. Its supported witness mechanics include first-parent distance, where
zero at the genuine base is valid, and reachable-history size when that is the
separately approved original algorithm. Neither is inferred to be Core3.1's
actual algorithm. No actual stage has a pinned `versionCountContract` yet;
unproven zero, positive fallback values, unknown algorithms and changed targets
fail. Tiny tests use clearly identified fixture targets, not claimed upstream
targets. Worker integration must pin the actual original algorithm/evaluation
inputs before invoking this boundary.

`verify_preferred_source` checks an explicitly pinned source manifest against
actual source-file Git blobs/modes, real Git tree/history objects, Gitlinks and
license members. It continues to report dependent generated/shared/submodule
qualification and original version-target qualification as unresolved. A map of
fingerprints alone does not validate the dependent source bodies. Current
preferred-source/license pins are unresolved, so current source admission fails.

The private SDK3.1.425 selection excludes **every** ELF by its bytes, including an
ELF renamed with a managed suffix. Selected SDK/packs/templates PE/data members
must match their actual materialized files. Only the separately recorded private
BundledVersions.props RID adaptation is permitted. This is private byte
accounting, not product identity, native runtime/provider qualification or a
license/compiler proof. Original global files, bootstrap ReadyToRun=0 and normal
product ReadyToRun/optimization remain separate obligations. This slice adds no
branding transformation to source bytes.

## Fresh parents, collector and admission boundary

`musl_legacy31_parents.py` validates a closed SDK/CPU/RID/musl/project/run/attempt/
image/code/policy context and disjoint declared source/bootstrap/work/report/
cache/product roots. It re-reads actual output files and raw parent documents;
child role identities must be exact fresh parent outputs. Required direct
consumption roles are explicit. An optional resolver or standalone SDK merely
present in a feed is not an inferred toolset restore. Source SDK tasks carried
through CLI.Runtime, exact restores/assets/caches, command/binlog authenticity,
physical ordinary roots and execution security still require independent worker
qualification. Metadata root declarations are not Linux isolation evidence.

Each stage needs raw original-version target/history witnesses. A proven zero
is permitted; conflicting argv/environment overrides fail. All stage results
are named **unqualified**, including successful small byte-accounting fixtures.
The selected native/crossgen file identities are checked, while their genuine
own construction and actual R2R consumption stay separate unresolved gates.

The collector repeats raw stage/parent/artifact/history validation instead of
accepting a cached graph-result dictionary. It authenticates its exact new collector-stage archive and every
final member's bytes/mode/link against a fresh output archive/layout or an exact
individually named unchanged import. It rejects unclassified members, bootstrap
dispositions, missing origins, changed imported bytes and unresolved import
member/license inventories. An explicit final TAR root directory also needs a
real origin with the same mode. An exact official import can establish candidate
byte correspondence; it stays unadmitted until source, stock provider and normal
qualification are independently closed. Modified selected compatibility/native
outputs require genuine own construction and consumption. There is no invented
requirement to rebuild every unchanged shipping native library.

Own-built origins must come from an upstream producing stage; the collector's
own archive/report roles can never provide circular self-lineage.

`musl_legacy31_admission.py` checks typed declarations for both native CPUs and
the complete named source/construction/original-scan/security/smoke/locale/TLS/
tracing/consumer report slots. It accepts no cached `passed` verdict as a gate.
Report fingerprints remain declarations, not validated report contents. Even a
complete fresh declaration returns all admission flags false, and
`require_normal_admission` rejects it. Historical71–81, bootstrap evidence and
another SDK's relabeled policy cannot pass. Registration requires future actual
independent gate implementations; changing booleans in this policy is rejected.
