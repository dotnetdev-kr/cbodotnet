# SDK6 native musl producer

The SDK6 implementation uses its own producer, evidence constructor and
independent admission contract. It does not select SDK7 construction, native,
framework or test policies. Shared functions parse bytes, archives, metadata,
binary logs and observed container security.

`musl_legacy_sdk6.py` builds the original SDK `1d205` and installer `d638` graphs with
the exact `6.0.135` native bootstrap. It consumes genuinely built NuGet `6.0.6-rc.4`,
VSTest `17.0.3-dev` and MSBuild.Localization `17.0.4-cbodotnet.1` packages. The original
NuGet TFMs, VSTest Core scope and thirteen cultures are retained. A real offline
NuGet PackageDownload restore primes exactly 22 source-package inputs; their raw
package bytes and original cache metadata are checked before and after tooling.

The original SDK source tree permits only the documented historical test-runtime
download skip and final resource-only translation layout hook. Product C# code,
the original target reference libraries and Full MSBuild task assets are kept.
The independent source contract verifies 190 SDK compiler outputs (including 9
references), 72 NuGet members, 304 VSTest outputs (including 3 references), 6 original
VSTest imports, 52 localization satellites and 286 original translation satellites.
The complete observed source/resource inputs of all five compiler components,
including the installer, are captured separately from original Git source.
The installer uses `/p:EmitCompilerGeneratedFiles=true` to retain observed compiler
generated inputs. Its complete original Git tree is recovered by reversing only
the exact reviewed `0001`, `0006` and `0007` GenerateLayout patches. Their complete
bytes must also be present in the archived orchestration. Other C# or target
changes, added hooks, exclusions and deleted source files are rejected.

Five native runtime products are built from f1dd with the two reviewed upstream
compatibility backports. The original version producer receives the same dated
properties during initial generation and original CoreCLR configuration. The
compiled version source/header must match those outputs; all five ELF markers,
debug sidecars, generated inputs, optimized compiler commands and every copy in
the final SDK are checked. An old fallback `42` native build cannot satisfy this
contract. Raw managed CLI metadata retains the original distribution behavior;
public branding remains the separately verified distribution wrapper.

Normal admission also requires the frozen native Docker image, observed non-root
UID/GID, dropped capabilities, no-new-privileges, default seccomp/AppArmor,
archived source/mount correspondence, exact tooling graph/properties and four
component/native worker envelopes. Cold and tracing workers accept only their
exact explicit environment and mount options. Volume/environment aliases,
shadow mounts and runtime overrides cannot bypass those checks. Final archive
verification, stock-provider ELF closure, default TLS trust and negative
certificate cases, archive-only LTTng and all 42 original tests are mandatory.
Reader admission binds both copied sources to archived orchestration and permits
only the clear-only NuGet configuration. It requires one exact bootstrap6.0.135
Reader build and five actual replay commands, then binds each original status,
binlog and task stream to the copies consumed by the component and installer
proofs. No second binary Reader execution is inferred from reparsing its JSON.
Named construction roles have fixed kinds and source identities; official musl
runtime and ASP.NET hashes cannot be bypassed by renaming their roles. The actual
SDK compiler package must equal the toolset in all three fingerprints, shared
framework files must retain their pinned archive or exact native origin, and the
generated and post-Crossgen snapshots must cover exactly validated task outputs.
The construction proof must bind the exact outer final SDK archive before source
validation starts, including for private diagnostic callers.

The private ARM64 integration archive `c2746`, zero-unknown constructor, full 82-root
source capture (928,514 files), 6,736 compiler-input files and all five actual native
copies have passed their independent stage-independent source checks. The
original 42 source/TRX/fixture audit records 41 passes, one original missing-poison
input skip and twelve OmniSharp scenarios. These observations do not establish
normal Docker boundaries or official two-CPU qualification. The interrupted
audit remains preserved; completed source gates and later successful remaining
gates are bound by immutable source, policy, package and manifest identities.

Routing, fresh normal ARM64/x64 producer runs, publication and consumer delivery
remain separate gates. Candidate registration keeps qualification, source
admission and release availability false until their actual evidence is reviewed.

Compiler worktrees and pristine imported-source parents can each retain a
Gitlink at the same commit. Collection preserves both physical source paths.
Imported component declarations select the unique
`source-for-serviced-imported-package` role, while compiled products keep their
actual compiler roots. Two pristine candidates remain ambiguous. Exact Git
trees, original blobs, complete archives and publisher-to-child Gitlink names
are still checked. A real two-parent Git fixture exercises collection, source
packing and independent verification without rewriting either child checkout.
